# Everglow Desktop PR

Process for committing changes and opening pull requests in Everglow Desktop. Every change travels by pull request with verified local checks and visual proof.

## 1. Branch hygiene

- Work on a topic branch created from latest `main`: `fix/...`, `feat/...`, `docs/...`, or `t3/...`. Never commit directly to `main`.
- Write small, scoped conventional commits: `feat(desktop): ...`, `fix(ui): ...`.
- Clean working directory before committing: discard ephemeral runtime caches (such as `vendor/ubol/_metadata/generated_indexed_rulesets/` generated by WebView2 extension runtime).

## 2. Local verification pipeline

Run all checks locally before opening the PR. Fix any failures before proceeding:

1. **Rust unit tests:**
   ```bash
   cargo test --manifest-path src-tauri/Cargo.toml
   ```
   Validates origin checks, update bridges, and adblock filter rules.

2. **Strict clippy:**
   ```bash
   cargo clippy --manifest-path src-tauri/Cargo.toml -- -D warnings
   ```
   Ensures zero warnings across Rust code.

3. **Release contract:**
   ```bash
   node --test scripts/release-contract.test.mjs
   ```
   Validates exact version agreement across `package.json`, `package-lock.json`, `src-tauri/tauri.conf.json`, `src-tauri/Cargo.toml`, and `src-tauri/Cargo.lock`.

4. **Native desktop test suite:**
   ```bash
   npm test
   ```
   (If port `18765` is busy, pass a port override: `EVERGLOW_VERIFY_PORT=19765 npm test`.)
   Spawns `everglow-desktop.exe --verify` with synthetic pages and checks animation, auto-hide, keyboard shortcuts, window controls, and ad blocking.

5. **Diff hygiene:**
   ```bash
   git diff --check
   ```

## 3. Visual proof

- For any UI change, capture screenshots in the running app and place them under `docs/pr-proof/<feature>/` or `evidence/`.
- Never use live production user data. The verification runner uses synthetic local test pages.
- Embed screenshots in the PR body using raw URLs pinned to the commit SHA:
  `![description](https://raw.githubusercontent.com/khentmoba/Everglow-Desktop/<commit-sha>/docs/pr-proof/<feature>/after.png)`

## 4. PR body format

Use the standard three-part PR structure without conversational filler:

### Summary
Small diff sketch or state diagram making the change obvious:
```diff
- Old behavior or structure
+ New behavior or structure
```

### Evidence
- **Before:** Baseline description or image.
- **After:** Pinned raw image URL of verified change.
- Exact commands run and pass counts recorded honestly.

### Merge Danger
- **Door:** `two-way` (revertible code changes without schema/installer lock-in) or `one-way` (breaking migrations, packaging format changes).
- **Blast Radius:** Scope of potential impact (e.g., `desktop UI`, `ad blocking`, `window controls`).
- **Safety Fact:** The single invariant proven by running tests rather than speculation.

## 5. Opening the PR

1. Stage explicit files, commit, and push the topic branch to `origin`.
2. Create the pull request using GitHub CLI:
   ```bash
   gh pr create --title "..." --body-file ...
   ```
3. Verify CI starts in GitHub Actions (`.github/workflows/desktop-checks.yml`) using:
   ```bash
   gh pr checks
   ```
4. Return the PR URL and check status. Merging and releases require separate authorization.
